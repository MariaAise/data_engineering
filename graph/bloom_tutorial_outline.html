0 Dataset at a Glance

Domain: FDA Adverse Event Reporting System (FAERS) — real-world pharmacovigilance data tracking adverse drug reactions reported to the FDA.

1 Setup Bloom Perspective ~3 min

1.1 — Open Explore tab and add categories

Explore → Add categories → select all 8 node labels

"Bloom needs to know which node types to visualize. Categories are Bloom's vocabulary — each one maps to a node label."

1.2 — Style the categories

Assign distinct colors to each label so the graph is readable at a glance:

2 Basic Search & Exploration ~5 min

2.1 — Natural language search

Search bar → type "Drug" → select a specific drug (e.g. "ASPIRIN")

"Bloom's search bar works like a near-natural-language interface. Type a category name to browse all nodes of that type, or type a specific name to jump straight to it."

2.2 — Expand a node

Right-click a Drug node → Expand → select relationship types to follow

"Expanding is how you traverse the graph visually. Each expansion follows one hop of relationships. You can choose which relationship types to follow — for a drug, expanding IS_PRIMARY_SUSPECT shows which adverse event cases it was the primary suspect in."

2.3 — Expand a second hop

Select a Case node → Expand → HAS_REACTION

"Now we've gone Drug → Case → Reaction in two hops. This is the core pharmacovigilance question: given a drug, what adverse reactions were reported?"

3 Pattern Search ~5 min

3.1 — Search a multi-node pattern

Search bar → type: "Drug ASPIRIN Case Reaction"

"Bloom understands chained patterns. By typing category-value-category-category, you're asking: show me all Cases involving ASPIRIN and their Reactions — in one query."

3.2 — Filter by relationship type

Search → "Drug IS_PRIMARY_SUSPECT Case"

"This narrows the search to only cases where the drug was the primary suspect, filtering out concomitant or secondary suspect roles. The distinction matters in pharmacovigilance — primary suspects have the strongest causal signal."

4 Investigating a Drug Safety Signal ~5 min

4.1 — Find a drug with many adverse cases

Search → "Drug" → pick a well-known drug → Expand IS_PRIMARY_SUSPECT

"We're looking for drugs with a high fan-out of primary suspect cases. A drug node connected to dozens of Case nodes is a potential safety signal worth investigating."

4.2 — Follow through to outcomes

Select multiple Case nodes → Expand → RESULTED_IN

"Now we can see the severity distribution — did these cases result in hospitalization, death, disability, or recovery? The Outcome nodes cluster and you can visually spot if one outcome dominates."

4.3 — Check the reactions

Select the same Case nodes → Expand → HAS_REACTION

"The Reaction nodes that appear most frequently across cases form the drug's adverse reaction profile. Shared Reaction nodes between many Cases are the strongest signals."

5 Cross-Drug Comparison ~5 min

5.1 — Load two drugs side by side

Search → "Drug ASPIRIN" → then search again → "Drug IBUPROFEN" (keep both on canvas)

"By loading two drugs onto the same canvas, we can visually compare their adverse event profiles. Shared Reaction nodes in the middle mean both drugs trigger the same side effect."

5.2 — Expand both and look for shared nodes

Expand both → IS_PRIMARY_SUSPECT → then expand Cases → HAS_REACTION

"Bloom automatically deduplicates — if both drugs share a Reaction node, it appears once with edges from both sides. These shared nodes are the visual fingerprint of overlapping safety profiles."

6 Filtering & Layout ~3 min

6.1 — Filter by property

Filter icon (funnel) → filter Cases by gender = "Female" or age group

"Bloom filters let you slice the visible graph without requerying. This is how you'd answer: are the adverse reactions different for female patients vs male patients?"

6.2 — Change layout

Bottom-right layout selector → try "Hierarchical" and "Force-based"

"Force-based layout clusters connected nodes together. Hierarchical shows the flow from Drug → Case → Reaction → Outcome. Choose based on what story you're telling."

6.3 — Rule-based styling

Settings → Rule-based styling → size Drug nodes by degree

"Sizing nodes by their connection count makes high-risk drugs visually pop — the more cases a drug is linked to, the larger it appears."

7 Demo Narrative — Tying It Together ~3 min

Story arc for a live walkthrough:

1. Start with a single drug (e.g. search "METFORMIN") — show the node in isolation

2. Expand to IS_PRIMARY_SUSPECT cases — show the fan-out, explain what "primary suspect" means

3. Expand cases to HAS_REACTION — see what side effects cluster

4. Expand cases to RESULTED_IN — see outcome severity

5. Filter to only "Death" outcomes — isolate the most severe signal

6. Expand those fatal cases back to other drugs (IS_CONCOMITANT) — were other drugs involved?

7. Conclude: "This is how pharmacovigilance analysts use graph databases to trace a safety signal from a single drug through patient cases to outcomes and co-prescribed drugs — in a way that would require multiple SQL joins across 6+ tables."
