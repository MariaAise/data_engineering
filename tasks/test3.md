 Purpose

The purpose of this assessment task is to:

LO 1. Deconstruct complex business problems to apply data mining and warehousing solutions, data requirements and data models using relational databases;

LO 2. Design and critically reflect upon data warehousing architecture and multidimensional data models using internal and external business data;

LO 3. Implement online analytical processing (OLAP) in SQL and devise business intelligence reports using data warehouses and OLAP; and,

LO 4. Critically evaluate big data processing frameworks and technologies, contextualise the use of NoSQL technologies, implement and critically evaluate streaming methods in the big data processing.

 Assessment Structure

Group-based (4 students)
30% Report + 10% Presentation

Scenario

You are hired by StreamWave (same company as in Assessment 2).

The company wants to:

Detect unusual streaming behaviour in near real-time.

Identify possible shared accounts across regions.

Ensure streaming data is reliable.

Control warehouse cost as data volume grows.

You must design a modern data architecture to support these goals.

You are not required to deploy real streaming systems.
You must design and prototype selected components.

What This Assessment Tests

Basic streaming concepts

Event-time vs processing-time understanding

Graph modelling in Neo4j

Architecture reasoning

Cost awareness

Collaboration

It does NOT test:

Advanced distributed systems setup

Production Kafka/Flink deployment

Complex SQL mechanics

Part 1 – Streaming System Design (Required)

Design a streaming pipeline that:

Ingests stream events

Calculates 10-minute tumbling window metrics

Detects one abnormal behaviour (group-specific)

You must include:

Event schema (table format)

Explanation of event time vs processing time

Tumbling window explanation (fixed 10 min)

Simple late data handling strategy (conceptual)

Basic duplicate mitigation idea (conceptual)

Storage layer choice (e.g., BigQuery)

You do NOT need:

Sliding windows

Watermark implementation

Code deployment

Architecture diagram is required.

Part 2 – Graph Use Case (Neo4j Prototype)

Goal: Detect possible account sharing.

You must:

Design simple graph schema:

User

Device

IP

Load small simulated dataset (generated using group seed)

Run 3 Cypher queries:

Find users sharing devices

Find high-degree users

Show connected clusters

You must briefly interpret results.

No advanced graph algorithms required.

Part 3 – Cost &amp; Scaling Strategy

Provide simple comparison:

Scenario	Batch Only	Streaming
Estimated cost logic	✔	✔

You must explain:

Why streaming may cost more

Partitioning strategy (date-based)

Basic hot vs cold data idea

What happens at 100M events/day (conceptual scaling explanation)

You do NOT need:

Exact pricing accuracy

Complex formulas

Full financial modelling

Part 4 – Failure &amp; Risk Analysis
