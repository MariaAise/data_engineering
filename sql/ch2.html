Window Functions

Window functions compute a value across a set of related rows without collapsing them. Unlike GROUP BY — which produces one row per group — a window function adds a new column to every existing row. The "window" is the set of rows it looks at for each calculation, defined by the OVER() clause.

OVER(PARTITION BY … ORDER BY …) RANK / DENSE_RANK ROW_NUMBER LAG / LEAD NTILE
Core Concept

The OVER() Clause — What Makes It a Window Function

Any aggregate or ranking function gains window behaviour when followed by OVER(...). Two parameters inside OVER control the window:

  • PARTITION BY col — divides rows into groups; the function restarts for each group. Omit it to treat all rows as one window.
  • ORDER BY col — defines row order within each partition. Required for ranking functions and LAG/LEAD. Determines what "previous" and "next" mean.

The key rule: Window functions are computed after WHERE and GROUP BY, but before ORDER BY and LIMIT. This means you cannot filter on a window function result in a WHERE clause in the same query — you must wrap it in a CTE or subquery first.

Window Function Quick Reference
ROW_NUMBER() OVER(...)Always unique: 1, 2, 3, 4 — no ties, no gaps
RANK() OVER(...)Ties share rank, gap after: 1, 1, 3, 4
DENSE_RANK() OVER(...)Ties share rank, no gap: 1, 1, 2, 3
NTILE(4) OVER(...)Divides rows into 4 equal buckets (1=bottom, 4=top)
LAG(col, 1) OVER(...)Value from the previous row (NULL if none)
LEAD(col, 1) OVER(...)Value from the next row (NULL if none)
SUM(col) OVER(...)Running or partitioned sum — see Chapter 04
Syntax Anatomy — OVER() Clause

Tasks
TASK 2.1 RANK — Rank Customers Within Each Plan by Total Spend
Business Question
For each customer, show their plan name, total completed payments, and their rank within that plan (rank 1 = highest spender). Show both RANK and DENSE_RANK so the difference is visible.
Thinking — How to Construct This Query
1Need totals first: Window functions operate on rows — you can't rank before you have the per-customer totals. Use a CTE to aggregate first.
2PARTITION BY plan_id: This resets the rank counter to 1 for each plan. Without it, you'd get a single global rank across all customers.
3ORDER BY total_paid DESC: Highest spender gets rank 1. Flip to ASC for "lowest = rank 1".
4RANK vs DENSE_RANK: If two customers tie at rank 1, RANK gives them both 1 and skips to 3. DENSE_RANK gives both 1 and continues at 2. Use DENSE_RANK when you need "no gaps" in ranking numbers.
Solution
WITH
customer_plan_totals AS (
    SELECT
        c.name,
        pl.plan_name,
        pl.plan_id,
        SUM(p.amount) AS total_paid
    FROM   payments  p
    JOIN   customers c  ON p.customer_id = c.customer_id
    JOIN   plans     pl ON p.plan_id     = pl.plan_id
    WHERE  p.status = 'completed'
    GROUP BY c.name, pl.plan_name, pl.plan_id
)
SELECT
    name,
    plan_name,
    total_paid,
    RANK() OVER (
        PARTITION BY plan_id
        ORDER BY     total_paid DESC
    ) AS rnk,
    DENSE_RANK() OVER (
        PARTITION BY plan_id
        ORDER BY     total_paid DESC
    ) AS dense_rnk
FROM   customer_plan_totals
ORDER BY plan_name, rnk;

TASK 2.2 LAG — Compare Each Payment to the Previous One
Business Question
For each customer's completed payments (ordered by date), show the current amount, the previous payment amount, and the difference. Useful for spotting payment growth or decline per account.
Thinking — How to Construct This Query
1LAG(col, n, default): Returns the value of col from n rows earlier within the window. The optional third argument is the default when no prior row exists (first row of a partition). If omitted, returns NULL.
2PARTITION BY customer_id: Each customer's payment history is its own independent window. The first payment per customer has no prior row, so LAG returns NULL (or the default).
3ORDER BY payment_date: Defines what "previous" means — the payment that came before this one chronologically.
4Computing delta: amount - LAG(amount, 1, amount) — using amount as default means when there's no prior row, delta = amount - amount = 0, which is cleaner than NULL arithmetic.
Solution
SELECT
    c.name,
    p.payment_date,
    p.amount                                     AS current_amount,

    LAG(p.amount, 1) OVER (
        PARTITION BY p.customer_id
        ORDER BY     p.payment_date
    )                                            AS prev_amount,

    p.amount - LAG(p.amount, 1, p.amount) OVER (
        PARTITION BY p.customer_id
        ORDER BY     p.payment_date
    )                                            AS delta

FROM   payments  p
JOIN   customers c ON p.customer_id = c.customer_id
WHERE  p.status = 'completed'
ORDER BY c.name, p.payment_date;

TASK 2.3 NTILE — Bucket Customers Into Spend Quartiles
Business Question
Divide all customers into 4 spend quartiles (Q1 = lowest 25%, Q4 = highest 25%). Return customer name, total spend, quartile number, and a readable label.
Thinking — How to Construct This Query
1NTILE(n): Distributes rows into n buckets as equally as possible. Bucket 1 = lowest values, bucket n = highest values (when ORDER BY ASC). If rows don't divide evenly, earlier buckets get one extra row.
2No PARTITION BY: We want quartiles across all customers, not within groups. Omitting PARTITION BY treats the entire result set as one window.
3CTE for totals first: NTILE operates on rows — aggregate payments per customer in a CTE, then apply NTILE in the outer query.
4Add a readable label: Wrap NTILE in a CASE expression. This avoids the caller needing to know that 4 = "top quartile".
Solution
WITH
totals AS (
    SELECT
        customer_id,
        SUM(amount) AS total_paid
    FROM   payments
    WHERE  status = 'completed'
    GROUP BY customer_id
)
SELECT
    c.name,
    t.total_paid,
    NTILE(4) OVER (
        ORDER BY t.total_paid ASC    -- ASC: Q1=lowest, Q4=highest
    )                                AS quartile,
    CASE NTILE(4) OVER (ORDER BY t.total_paid ASC)
        WHEN 1 THEN 'Q1 · Low'
        WHEN 2 THEN 'Q2 · Mid-Low'
        WHEN 3 THEN 'Q3 · Mid-High'
        WHEN 4 THEN 'Q4 · Top'
    END                              AS quartile_label
FROM   totals    t
JOIN   customers c ON t.customer_id = c.customer_id
ORDER BY t.total_paid ASC;
