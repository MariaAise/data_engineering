Top-N Per Group

LIMIT 3 returns the top 3 rows globally. Getting the top 3 within each category, plan, or region requires a different pattern: assign a rank number to each row within its group using ROW_NUMBER(), wrap it in a CTE, then filter on that rank. This pattern appears constantly in real analytics work.

ROW_NUMBER() OVER (PARTITION BY …) Filter on rn <= N Most recent per customer
Core Concept

Why LIMIT Doesn't Work Per Group

ORDER BY revenue DESC LIMIT 2 returns the global top 2 rows. It has no awareness of groups. There is no syntax like LIMIT 2 PER plan in standard SQL.

The solution is a two-step pattern that combines what you learned in chapters 1 and 2:

  • Step 1 — Rank within group: Use ROW_NUMBER() OVER (PARTITION BY group_col ORDER BY metric DESC) to assign a sequential number to each row within its group. The best row in each group gets rn=1, second best gets rn=2, and so on.
  • Step 2 — Filter on rank: Wrap step 1 in a CTE. In the outer query, WHERE rn <= N keeps only the top N per group.

ROW_NUMBER vs RANK for top-N: Use ROW_NUMBER when you want exactly N rows per group regardless of ties. Use RANK when ties should both be included (may return more than N rows if there's a tie at position N).

The Top-N Per Group Template
WITH ranked AS (← Step 1: rank rows within each group
SELECT *,
ROW_NUMBER() OVER (always unique — no ties within a partition
PARTITION BY group_col← restart numbering for each group
ORDER BY metric_col DESC← what defines "top"
) AS rn
FROM source_cte_or_table
)
SELECT * FROM ranked← Step 2: filter to top N per group
WHERE rn <= 2;change N to whatever you need
⚠️
Why can't we filter in the same SELECT? Window functions are evaluated after WHERE. You cannot write WHERE ROW_NUMBER() OVER(...) <= 2 — the WHERE runs before the window function has been computed. The CTE forces evaluation first, making the result available to filter on.
Tasks
TASK 3.1 Top 2 Paying Customers Per Plan
Business Question
For each plan, find the top 2 customers by total completed payment amount. Return plan name, customer name, total paid, and their rank within the plan.
Thinking — How to Construct This Query
1CTE 1 — totals: Aggregate payments per customer+plan. This is the source data for ranking — one row per customer per plan.
2CTE 2 — ranked: Apply ROW_NUMBER() OVER (PARTITION BY plan_id ORDER BY total_paid DESC) to CTE 1. This assigns rn=1 to the highest spender in each plan, rn=2 to the second, etc.
3Main query: SELECT from ranked WHERE rn <= 2. JOIN to customers and plans for readable names.
4Three CTEs vs one: You could combine steps 1 and 2 into one CTE by joining and aggregating there. Splitting them makes the logic easier to test incrementally — run just CTE 1 to verify the aggregation before adding the ranking layer.
Solution
WITH
-- Step 1: aggregate per customer per plan
totals AS (
    SELECT
        p.customer_id,
        p.plan_id,
        SUM(p.amount) AS total_paid
    FROM   payments p
    WHERE  p.status = 'completed'
    GROUP BY p.customer_id, p.plan_id
),
-- Step 2: rank within each plan
ranked AS (
    SELECT
        customer_id,
        plan_id,
        total_paid,
        ROW_NUMBER() OVER (
            PARTITION BY plan_id
            ORDER BY     total_paid DESC
        ) AS rn
    FROM totals
)
-- Step 3: filter and join for readable output
SELECT
    pl.plan_name,
    c.name          AS customer_name,
    r.total_paid,
    r.rn            AS rank_in_plan
FROM   ranked    r
JOIN   customers c  ON r.customer_id = c.customer_id
JOIN   plans     pl ON r.plan_id     = pl.plan_id
WHERE  r.rn <= 2
ORDER BY pl.plan_name, r.rn;

TASK 3.2 Most Recent Payment Per Customer
Business Question
For each customer, return their single most recent completed payment — including the date, amount, and plan name. One row per customer.
Thinking — How to Construct This Query
1"Most recent per customer" = top-1 per group. This is the same pattern as Task 3.1 with N=1 and a different ORDER BY.
2ORDER BY payment_date DESC: The most recent date = largest date value = rank 1 when ordering descending.
3Why not MAX(payment_date)? SELECT customer_id, MAX(payment_date) gives you the date, but not the other columns from that row (amount, plan_id). The ROW_NUMBER pattern keeps the entire row intact.
4Tiebreak: If a customer has two payments on the same date, ROW_NUMBER will arbitrarily pick one. Add a secondary ORDER BY (e.g. payment_id DESC) to make the tiebreak deterministic.
Solution
WITH
ranked_payments AS (
    SELECT
        p.customer_id,
        p.payment_date,
        p.amount,
        p.plan_id,
        ROW_NUMBER() OVER (
            PARTITION BY p.customer_id
            ORDER BY     p.payment_date DESC,
                         p.payment_id   DESC  -- tiebreak
        ) AS rn
    FROM   payments p
    WHERE  p.status = 'completed'
)
SELECT
    c.name           AS customer,
    rp.payment_date  AS last_payment_date,
    rp.amount        AS last_amount,
    pl.plan_name     AS last_plan
FROM   ranked_payments rp
JOIN   customers       c  ON rp.customer_id = c.customer_id
JOIN   plans           pl ON rp.plan_id     = pl.plan_id
WHERE  rp.rn = 1
ORDER BY rp.payment_date DESC;
