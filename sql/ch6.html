Chapter 06 · MySQL 8.0

Date Arithmetic & Time-Series Gaps

Date analysis is where SQL meets business reality. How long since a customer paid? Which months had zero revenue? What's the average gap between transactions? These questions require date functions, gap detection via LEFT JOIN + IS NULL, and combining LAG with DATEDIFF to measure time between events.

DATEDIFF · DATE_ADD · CURDATE Gap detection via LEFT JOIN IS NULL LAG + DATEDIFF Date spine
Core Concept

Essential MySQL Date Functions

MySQL has a rich set of date functions. The ones you'll use most in analytics:

  • DATEDIFF(date1, date2) — returns date1 minus date2 in days (positive if date1 is later)
  • DATE_ADD(date, INTERVAL n MONTH) — add n months to a date
  • CURDATE() — today's date
  • DATE_FORMAT(date, '%Y-%m') — format as 'YYYY-MM' string
  • MONTH(date) / YEAR(date) / QUARTER(date) — extract parts
  • LAST_DAY(date) — last day of the month containing that date

Gap detection: The LEFT JOIN + IS NULL pattern from Level 1 applies to time-series too. Build a complete sequence of expected months (a "date spine"), LEFT JOIN your actual data onto it, and any month with IS NULL in the data side is a gap.

Date Function Quick Reference
DATEDIFF(CURDATE(), last_payment_date)days since last payment (positive = in the past)
DATE_ADD(payment_date, INTERVAL 30 DAY)30 days after payment_date
DATE_FORMAT(payment_date, '%Y-%m')format as '2024-03' for month grouping
LAST_DAY('2024-02-01')returns '2024-02-29' — useful for month-end logic
PERIOD_DIFF(EXTRACT(…), EXTRACT(…))difference in months between two year-month values
Tasks
TASK 6.1 Days Since Last Payment Per Customer
Business Question
For each customer, find the date of their most recent completed payment and calculate how many days ago that was (relative to 2024-12-01 as "today" for reproducibility). Return customer name, last_payment_date, and days_since_payment.
Thinking — How to Construct This Query
1CTE — most recent date per customer: GROUP BY customer_id, MAX(payment_date). This is the simplest way to get one row per customer with their latest date.
2DATEDIFF: DATEDIFF('2024-12-01', last_payment_date) gives the number of days between those two dates. We use a fixed reference date instead of CURDATE() so the result is reproducible — in production you'd use CURDATE().
3Ordering: Order by days_since_payment DESC to surface customers who haven't paid recently at the top — the most at-risk accounts.
Solution
WITH
last_payments AS (
    SELECT
        customer_id,
        MAX(payment_date) AS last_payment_date
    FROM   payments
    WHERE  status = 'completed'
    GROUP BY customer_id
)
SELECT
    c.name,
    lp.last_payment_date,
    DATEDIFF('2024-12-01', lp.last_payment_date) AS days_since_payment
FROM   last_payments lp
JOIN   customers     c ON lp.customer_id = c.customer_id
ORDER BY days_since_payment DESC;

TASK 6.2 Churned Customers — No Payment in Last 90 Days
Business Question
Flag customers whose most recent payment was more than 90 days ago (relative to 2024-12-01). These are potentially churned accounts. Return their name, segment, last payment date, and days since payment.
Thinking — How to Construct This Query
1Build on Task 6.1: The CTE structure is the same. Add a WHERE filter on the outer query for days_since_payment > 90.
2Alternative date approach: Instead of computing days and filtering, you can filter directly on the date: WHERE last_payment_date < DATE_SUB('2024-12-01', INTERVAL 90 DAY). Both approaches produce the same result — the days calculation is useful when you also want to display the number.
3Include segment: Join to customers for the segment column — useful for analysing whether churn is concentrated in SMB vs Enterprise customers.
Solution
WITH
last_payments AS (
    SELECT
        customer_id,
        MAX(payment_date) AS last_payment_date
    FROM   payments
    WHERE  status = 'completed'
    GROUP BY customer_id
),
days_since AS (
    SELECT
        lp.customer_id,
        lp.last_payment_date,
        DATEDIFF('2024-12-01', lp.last_payment_date) AS days_since_payment
    FROM last_payments lp
)
SELECT
    c.name,
    c.segment,
    ds.last_payment_date,
    ds.days_since_payment,
    CASE
        WHEN ds.days_since_payment > 180 THEN 'High Risk'
        WHEN ds.days_since_payment > 90  THEN 'At Risk'
        ELSE                                   'Active'
    END AS churn_flag
FROM   days_since ds
JOIN   customers  c ON ds.customer_id = c.customer_id
WHERE  ds.days_since_payment > 90
ORDER BY ds.days_since_payment DESC;
Expected Output — customers with no payment in 90+ days

TASK 6.3 Missing Months — Months in the Calendar With No Revenue
Business Question
Find all months in 2024 (Jan through Nov) that had zero completed revenue. Return the missing month numbers. Use a date spine to generate the complete list of expected months.
Thinking — How to Construct This Query
1The gap detection pattern: Build a complete set of expected months (the "date spine"), then LEFT JOIN your actual data. Months with no matching data have NULL in the right-side columns — those are the gaps.
2Generating a date spine in MySQL: MySQL doesn't have a native sequence generator. The cleanest method is a recursive CTE that generates numbers 1–11 (or 1–12) by adding 1 in each iteration.
3LEFT JOIN + IS NULL: LEFT JOIN the spine to a grouped payments summary. Months with no payments have NULL in the revenue column — WHERE revenue IS NULL keeps only the gaps.
Solution
WITH RECURSIVE
-- Generate month numbers 1 through 11 (Jan–Nov 2024)
month_spine AS (
    SELECT 1 AS month                       -- anchor: start at January
    UNION ALL
    SELECT month + 1                          -- recursive: add 1 each step
    FROM   month_spine
    WHERE  month < 11                        -- stop at November
),
-- Months that actually have payments
revenue_months AS (
    SELECT DISTINCT
        MONTH(payment_date) AS month
    FROM   payments
    WHERE  status = 'completed'
      AND  YEAR(payment_date) = 2024
)
-- LEFT JOIN spine to actuals; nulls = missing months
SELECT
    ms.month                    AS missing_month
FROM       month_spine     ms
LEFT JOIN  revenue_months  rm  ON ms.month = rm.month
WHERE      rm.month IS NULL
ORDER BY   ms.month;
Expected Output — month 1 (January) has no payments
missing_month
1
💡
WITH RECURSIVE: This is the first recursive CTE in the guide. The pattern is always the same: an anchor SELECT (starting value), UNION ALL, a recursive SELECT that references the CTE name and adds to the value, and a WHERE clause that sets the stopping condition. MySQL 8.0 fully supports recursive CTEs.
TASK 6.4 Average Days Between Consecutive Payments Per Customer
Business Question
For each customer with more than one payment, calculate the average number of days between consecutive completed payments. This indicates payment cadence — useful for predicting the next expected payment.
Thinking — How to Construct This Query
1Combining LAG + DATEDIFF: LAG gives you the previous payment date. DATEDIFF gives you the gap in days between two dates. Together: DATEDIFF(payment_date, LAG(payment_date) OVER (PARTITION BY customer_id ORDER BY payment_date)) gives the days since the previous payment, per customer.
2First payment per customer has no prior row — LAG returns NULL, so DATEDIFF returns NULL. We need to exclude these NULLs from the average.
3CTE approach: CTE 1 computes the gap for every payment row. CTE 2 averages those gaps per customer, excluding NULLs (AVG ignores NULLs automatically). Filter to customers with at least 2 payments.
4ROUND: Average days is cleaner as a whole number or one decimal — wrap in ROUND(…, 0) for readability.
Solution
WITH
-- Step 1: compute days since previous payment per row
payment_gaps AS (
    SELECT
        customer_id,
        payment_date,
        DATEDIFF(
            payment_date,
            LAG(payment_date, 1) OVER (
                PARTITION BY customer_id
                ORDER BY     payment_date
            )
        ) AS days_gap     -- NULL for first payment per customer
    FROM   payments
    WHERE  status = 'completed'
),
-- Step 2: average the gaps (AVG ignores NULLs automatically)
avg_gaps AS (
    SELECT
        customer_id,
        ROUND(AVG(days_gap), 0)  AS avg_days_between,
        COUNT(days_gap)            AS gap_count  -- rows used in average
    FROM   payment_gaps
    GROUP BY customer_id
    HAVING   COUNT(days_gap) >= 1  -- at least 2 payments (1 gap)
)
SELECT
    c.name,
    ag.avg_days_between,
    ag.gap_count  AS payment_intervals_measured
FROM   avg_gaps  ag
JOIN   customers c ON ag.customer_id = c.customer_id
ORDER BY ag.avg_days_between ASC;
