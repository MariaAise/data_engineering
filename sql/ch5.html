Conditional Aggregation

Conditional aggregation turns distinct row values into separate columns — the SQL equivalent of a pivot table, without needing a PIVOT keyword. The pattern is SUM(CASE WHEN category = 'X' THEN value ELSE 0 END) repeated for each category you want as a column. The result is a wide table instead of a tall one, often exactly what reporting and dashboards need.

SUM(CASE WHEN … THEN … ELSE 0 END) COUNT(CASE WHEN …) Pivot without PIVOT
Core Concept

Rows → Columns: The CASE Inside an Aggregate Pattern

Normally, GROUP BY plan_name gives you one row per plan. Sometimes you want one row per customer with columns for each plan. That requires conditional aggregation.

The mental model: For each row, CASE evaluates whether it belongs to a given category. If yes, it passes the value to the aggregate. If no, it passes 0 (for SUM) or NULL (for COUNT). The aggregate then adds up only the matching values.

  • SUM(CASE WHEN plan = 'Pro' THEN amount ELSE 0 END) — revenue from Pro payments only
  • COUNT(CASE WHEN status = 'open' THEN 1 END) — count of open items (NULL values ignored by COUNT)
  • MAX(CASE WHEN plan = 'Enterprise' THEN amount END) — max value for Enterprise rows

When to use it: When a stakeholder asks for a report where each row is a customer/product/region and the columns represent categories. Also useful for creating heatmaps, comparison tables, and crosstabs directly in SQL.

Syntax Anatomy — Conditional Aggregation
SELECT← one row per group_col value
group_col,
SUM(CASE WHEN category = 'Basic' THEN amount ELSE 0 END) AS basic_rev,← one column per category
SUM(CASE WHEN category = 'Pro' THEN amount ELSE 0 END) AS pro_rev,← same pattern, different filter
SUM(CASE WHEN category = 'Enterprise' THEN amount ELSE 0 END) AS ent_rev
FROM source_table
GROUP BY group_col;← GROUP BY collapses to one row per group
SUM(CASE … ELSE 0)

Use ELSE 0 for revenue/quantity columns. Non-matching rows contribute 0 to the sum, so the total is always meaningful — never NULL.

COUNT(CASE … END)

Omit ELSE for count columns. COUNT ignores NULLs, so non-matching rows (which return NULL) aren't counted. ELSE NULL is the same as omitting ELSE.

Tasks
TASK 5.1 Revenue by Plan as Columns — One Row Per Customer
Business Question
For each customer, show how much they paid on each plan (Basic, Pro, Enterprise) as separate columns. Also include a total column. One row per customer.
Thinking — How to Construct This Query
1The shape we want: One row per customer. Three plan columns. Each column should show that customer's spend on that specific plan, or 0 if they never used it.
2GROUP BY customer_id: One row per customer. Then for each plan column, a conditional SUM that only adds payments matching that plan.
3Total column: Just SUM(amount) with no condition — adds up everything regardless of plan.
4JOIN to plans for plan_name: The payments table has plan_id (integer). JOIN to plans to get the name string used in the CASE condition, or compare against plan_id integers directly.
Solution
SELECT
    c.name                                                                  AS customer,
    SUM(CASE WHEN pl.plan_name = 'Basic'       THEN p.amount ELSE 0 END)  AS basic_rev,
    SUM(CASE WHEN pl.plan_name = 'Pro'         THEN p.amount ELSE 0 END)  AS pro_rev,
    SUM(CASE WHEN pl.plan_name = 'Enterprise'  THEN p.amount ELSE 0 END)  AS enterprise_rev,
    SUM(p.amount)                                                           AS total_rev
FROM   payments  p
JOIN   customers c  ON p.customer_id = c.customer_id
JOIN   plans     pl ON p.plan_id     = pl.plan_id
WHERE  p.status = 'completed'
GROUP BY c.customer_id, c.name
ORDER BY total_rev DESC;

TASK 5.2 Support Tickets by Status — Count Columns Per Customer
Business Question
For each customer, show how many support tickets they have in each status (open, closed) as separate columns, plus a total ticket count. This is a customer health indicator.
Thinking — How to Construct This Query
1COUNT instead of SUM: We're counting rows, not summing a numeric column. Use COUNT(CASE WHEN status = 'open' THEN 1 END) — the CASE returns 1 for open tickets and NULL otherwise; COUNT ignores NULLs, so only open tickets are counted.
2No ELSE needed for COUNT: If you write ELSE 0, COUNT would still count the 0 values (COUNT counts non-NULL values, and 0 is not NULL). Either omit ELSE or use ELSE NULL explicitly.
3Total column: COUNT(*) or COUNT(ticket_id) with no condition counts all tickets regardless of status.
Solution
SELECT
    c.name                                                              AS customer,
    COUNT(CASE WHEN t.status = 'open'   THEN 1 END)                  AS open_tickets,
    COUNT(CASE WHEN t.status = 'closed' THEN 1 END)                  AS closed_tickets,
    COUNT(t.ticket_id)                                                  AS total_tickets,
    COUNT(CASE WHEN t.priority = 'high' AND t.status = 'open' THEN 1 END) AS high_open
FROM   customers       c
LEFT JOIN support_tickets t ON c.customer_id = t.customer_id
GROUP BY c.customer_id, c.name
ORDER BY open_tickets DESC, total_tickets DESC;

TASK 5.3 Monthly Revenue Heatmap — Quarters as Columns
Business Question
Create a monthly revenue breakdown with one row per month and one column per quarter label (Q1, Q2, Q3, Q4). Non-matching months show 0. This gives a heatmap-style view of revenue concentration by quarter.
Thinking — How to Construct This Query
1CTE first: Aggregate revenue by month and compute the quarter number using QUARTER(payment_date) or a CASE on the month number.
2Outer query: GROUP BY month again. For each quarter column, SUM(CASE WHEN quarter = 1 THEN monthly_revenue ELSE 0 END). Since each month belongs to exactly one quarter, this just returns the monthly_revenue or 0.
3Why not GROUP BY quarter? Grouping by quarter collapses the months together. We want each month as its own row with a visual column indicator showing which quarter it falls in — good for spotting seasonality.
Solution
WITH
monthly AS (
    SELECT
        MONTH(payment_date)    AS month,
        QUARTER(payment_date)  AS quarter,
        SUM(amount)            AS monthly_revenue
    FROM   payments
    WHERE  status = 'completed'
      AND  YEAR(payment_date) = 2024
    GROUP BY MONTH(payment_date), QUARTER(payment_date)
)
SELECT
    month,
    SUM(CASE WHEN quarter = 1 THEN monthly_revenue ELSE 0 END)  AS Q1,
    SUM(CASE WHEN quarter = 2 THEN monthly_revenue ELSE 0 END)  AS Q2,
    SUM(CASE WHEN quarter = 3 THEN monthly_revenue ELSE 0 END)  AS Q3,
    SUM(CASE WHEN quarter = 4 THEN monthly_revenue ELSE 0 END)  AS Q4,
    monthly_revenue                                                  AS total
FROM   monthly
GROUP BY month, monthly_revenue
ORDER BY month;
