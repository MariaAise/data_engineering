Understanding
SQL JOINs

A JOIN combines rows from two or more tables based on a related column between them. Instead of storing everything in one giant table, relational databases split data into smaller focused tables and use JOINs to bring them together exactly when needed.

Think of it like a spreadsheet VLOOKUP — but far more powerful. Every JOIN type answers a slightly different question about which rows to include when the data in two tables doesn't perfectly overlap.

01
Most Common
INNER JOIN
Returns only the rows that have a matching value in both tables. If a row in the left table has no match in the right table (or vice versa), it is completely excluded from the result. This is the default JOIN — writing JOIN without a keyword means INNER JOIN.

Ask yourself: "Give me employees and their department — only where both exist."

02
Second Most Common
LEFT JOIN
Returns all rows from the left table, plus any matching rows from the right table. When there's no match on the right side, the right-side columns come back as NULL.

Ask yourself: "Give me ALL employees — and their department if they have one." The left table is always the one in FROM.

03
Mirror of LEFT JOIN
RIGHT JOIN
The mirror image of LEFT JOIN. Returns all rows from the right table, plus any matching rows from the left table. Left-side columns come back as NULL where there's no match.

Ask yourself: "Give me ALL departments — and their employees if there are any." In practice most developers rewrite RIGHT JOINs as LEFT JOINs by swapping table order — it's easier to read.

04
Everything from Both
FULL OUTER JOIN
Returns all rows from both tables. Where a match exists, columns from both sides are filled in. Where there's no match, the missing side's columns come back as NULL.

Ask yourself: "Give me every employee AND every department — whether or not they're linked." MySQL doesn't support FULL OUTER JOIN natively — emulate it with LEFT JOIN UNION RIGHT JOIN.

05
A Table Joined to Itself
SELF JOIN
A self join joins a table to itself. This sounds strange but is useful whenever a table has a column that references another row in the same table — like employees who have managers, categories with parent categories, or comments with replies.

Ask yourself: "Show each employee alongside their manager's name" — both pieces of data live in the same employees table. You must use two different aliases so MySQL can tell the copies apart.

SQL — alias the table twice
-- 'e' = the employee, 'm' = their manager
-- Both aliases point to the same table

SELECT
    e.name        AS employee,
    e.role,
    m.name        AS manager
FROM      employees e
LEFT JOIN employees m
       ON e.manager_id = m.emp_id
ORDER BY m.name;

06
Every Combination
CROSS JOIN
Produces the cartesian product — every row from the left table paired with every row from the right table. No ON condition is needed or used. If the left table has 4 rows and the right has 4 rows, you get 4 × 4 = 16 rows.

Use cases: Generating all size/color combinations for a product catalogue, creating a calendar grid (all months × all years), seeding test data. Be careful — on large tables this creates enormous result sets.

07
Find What Doesn't Match
ANTI-JOIN (LEFT JOIN + WHERE IS NULL)
An anti-join isn't a keyword — it's a pattern that finds rows in one table that have no corresponding row in another. You do a LEFT JOIN and then filter with WHERE right_table.id IS NULL.

Use cases: Find customers who have never placed an order. Find employees with no department. Find products that have never been sold. Find records in table A that are missing from table B.

Quick Reference — All JOINs at a Glance
JOIN Type What it returns When to use it Rows from sample
INNER JOIN Only rows matched in both tables You want clean data — only fully linked records 3 (excludes Sam + empty depts)
LEFT JOIN All left rows + matched right (NULLs for non-matches) You want all left records regardless of whether the right side exists 4 (Sam included with NULL)
RIGHT JOIN All right rows + matched left (NULLs for non-matches) Same as LEFT but from the right side — usually rewritten as LEFT for clarity 5 (Marketing + Legal with NULL)
FULL OUTER JOIN All rows from both tables, NULLs on either unmatched side Audit / reconciliation — find everything missing on either side. Use UNION in MySQL. 6 (everything)
SELF JOIN A table joined to itself Hierarchical data — employees/managers, categories/subcategories 4 (each employee with their manager)
CROSS JOIN Every row × every row (cartesian product) Generate all combinations — sizes × colours, months × years 16 (4 × 4 employees × departments)
ANTI-JOIN (pattern) Rows in left table with no match in right Find orphans — customers with no orders, products never sold, missing data 1 (Sam only) or 2 (Marketing, Legal)
📌
Golden rules
Always alias your tables when joining (e, d). Always qualify column names with their alias (e.name not just name). Always specify an ON condition — a JOIN without ON is a CROSS JOIN.
📌
NOT IN vs anti-join
Avoid WHERE id NOT IN (subquery) when the subquery might return NULLs — it will silently return zero rows. Use LEFT JOIN … WHERE IS NULL or NOT EXISTS instead.
